# 0003. Локальный Git workflow системных требований

## Объем

Доступны status, сравнение сохраненных документов с HEAD, история и ручная фиксация выбранных документов. Сохранение Markdown не создает коммит. Автоматических коммитов исходного кода нет.

Git CLI вызывается без shell с отдельными аргументами, literal pathspecs и отключенным fsmonitor. Для текстового diff используется jsdiff: сравнение строится по уже прочитанным байтам, а не повторно читаемому во время сравнения файлу.

Рабочая папка может быть подпапкой существующего репозитория. Git-пути переводятся относительно нее. В статус, diff, историю и коммит допускаются только системные требования; для удаления тип проверяется по предыдущей версии. Исходный код и другие документы не входят в управляемый набор. Репозиторий без HEAD поддерживается; автоматически создавать репозиторий приложение не будет.

## Снимок просмотра

Токен снимка включает HEAD, полное имя ветки, путь, сохраненное содержание, состояние удаления и режим файла. Запрос фиксации передает токены просмотренных документов. Сервер повторно читает состояние и отклоняет устаревшие снимки. После проверки в Git попадают именно проверенные байты через hash-object, без подмены более свежим файлом.

Создание, сохранение и Git-фиксация используют общую очередь рабочего пространства. Сохраняется ограничение одного API-процесса; параллельная запись внешними программами во время операции не поддерживается.

## Временный индекс и публикация

Перед подготовкой проверяется отсутствие чужих staged-изменений, включая intent-to-add. Подготовка идет в копии индекса, сохраняющей флаги незатронутых записей. Только выбранные требования добавляются в эту копию. git write-tree и commit-tree создают объекты, но до публикации ссылка ветки и основной индекс не меняются.

До изменения HEAD журнал содержит базовую версию, новый коммит и хеши старого и подготовленного индекса. Подготовленная копия публикуется как index.lock через hard link к уникальному файлу приложения в Git-dir. Это позволяет доказать принадлежность блокировки по inode даже после остановки процесса.

После захвата блокировки повторно проверяются HEAD, ветка и исходный индекс. update-ref использует ожидаемый старый OID. Затем index.lock атомарно заменяет основной индекс. Невыбранные файлы и посторонние рабочие изменения не фиксируются и не сбрасываются.

## Восстановление

Если HEAD остался базовым, собственная подготовка отменяется без изменения файлов и основного индекса. Если HEAD равен созданному коммиту, принадлежащая приложению блокировка завершается публикацией подготовленного индекса. После этого повтор операции возвращает прежний хеш без второго коммита.

Блокировка, не связанная с уникальным файлом приложения, не удаляется. Неожиданная ветка, HEAD или индекс переводят операцию в needs_review и блокируют следующие фиксации до разбора. Автоматического reset нет.

UI сохраняет ID и параметры незавершенной фиксации в sessionStorage вкладки. При потере ответа проверяется GET /git/operations/:id. Повтор с тем же ID возвращает состояние исходной операции; другой payload с тем же ID отклоняется.

## Ограничения

Локальная версия использует commit-tree и не выполняет commit hooks или подписание. PR/MR, push/pull, смена веток и разрешение конфликтов вынесены в следующий этап. История постраничная, для merge-коммита сравнение строится с первым родителем. Упрощение удаленного сценария не считается проверенным этой реализацией.

## Проверка

Интеграционные тесты выполняются только во временных репозиториях. Проверяются: вложенная рабочая папка, ограничения по типу документов, выбранный набор, чужой индекс, устаревший снимок, повтор запроса, удаление, остановка до и после обновления HEAD. В тестах восстановление после публикации HEAD также проверяет согласованность обычного индекса.

Официальные источники: [git-status](https://git-scm.com/docs/git-status), [git-update-ref](https://git-scm.com/docs/git-update-ref), [git-commit-tree](https://git-scm.com/docs/git-commit-tree), [jsdiff](https://github.com/kpdecker/jsdiff).
