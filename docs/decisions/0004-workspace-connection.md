# 0004. Подключение независимого репозитория

Статус: принято.

## Решение

Выбор существующего локального Git-репозитория доступен в верхней панели. Это переключение одного активного рабочего пространства, а не вкладки нескольких проектов. Начальная папка задается `SPECIDE_WORKSPACE`; к ней можно вернуться без удаления подключенных документов.

`WorkspaceManager` владеет парой DocumentsService/GitService для текущей папки. Все обращения контроллеров и переключения проходят через одну очередь. Сервисы не меняют корень во время запроса. Выбор записывается атомарно в `.specide/connection.json` до публикации нового контекста; после перезапуска он восстанавливается. Недоступное подключение приводит к возврату в исходную папку с видимым предупреждением.

Путь проверяется через realpath: нужен корень рабочего Git-репозитория, не вложенная папка, bare-хранилище или URL. Пересечения с кодом продукта и служебными данными запрещены. Worktree продукта определяется по общему Git-хранилищу и также запрещен. Git не инициализируется и не конфигурируется автоматически.

## Изоляция и восстановление

Стабильный `storageKey` вычисляется по каноническому пути. Журналы внешних репозиториев находятся в `.specide/workspaces/<storageKey>/`; исходная папка сохраняет прежнее расположение журнала. Браузерные pending-запросы документов и Git используют тот же ключ. Повторное подключение папки не теряет журнал. Завершенные `needs_review` сохраняются для разбора, но не блокируют уход из проекта; незавершенные `pending` блокируют переключение.

Идентификатор активного контекста меняется при каждом переключении и переживает перезапуск. Клиент отправляет его в `X-Specide-Workspace`; для изменений он обязателен. Запрос старой вкладки отклоняется с `WORKSPACE_CHANGED`, даже если новый репозиторий содержит такой же ID документа. Клиент сохраняет черновик в памяти и предлагает перезагрузку, не обновляя привязку автоматически.

`POST /workspace/connect` принимает `operationId`, `expectedWorkspaceId` и `path` (null означает исходную папку). Повтор последнего запроса идемпотентен. `GET /workspace/connections/:operationId` позволяет проверить потерянный ответ. Старый запрос не может повторно переключить проект после другого подключения: expectedWorkspaceId уже не совпадает. Успех обновляет интерфейс полной перезагрузкой, чтобы исключить перенос кэша документов между папками.

## Границы

Это локальное приложение с одним API-процессом и одним активным проектом. Клонирование, удаленные учетные данные, push/pull и многопользовательская работа не входят в этот срез. Подключение не означает конвертацию произвольного Markdown в требования. Новый репозиторий может быть пустым; файлы появляются только при создании требования пользователем.
